# RLPD 预训练方案：针对长程任务的优化

## 一、问题背景

### 1.1 原始 RLPD 在长程任务中的困境

HIL-SERL 论文中的 RLPD 算法在 **短程任务**（~100 步，~10 秒）上表现优异，但论文中所有复杂装配任务都被分解为短程子任务后独立训练。论文在 Discussion 部分明确承认：

> *"it remains uncertain whether this method can be further extended to tasks with significantly longer horizons, where the sample complexity issue becomes more pronounced."*

我们的 gear assembly 任务特性与论文任务差异巨大：

| 指标 | HIL-SERL 论文任务 | Gear Assembly |
|------|-------------------|---------------|
| 演示轨迹平均步数 | ~100 步 | **~548 步** |
| Max Episode Length | 100 步 | **900 步** |
| 任务时长（10Hz） | ~10 秒 | **~55 秒** |
| Bellman 起点 Q 值（γ=0.97） | 0.97^100 ≈ 0.048 | 0.97^548 ≈ **1.7e-8** |

### 1.2 核心问题分析

直接使用原始 RLPD（50/50 采样 + γ=0.97）训练长程任务会导致：

1. **折扣因子的数学屏障**：γ=0.97 的有效视野仅 ~33 步（1/(1-0.97)=33）。超过 33 步的奖励信号衰减到可以忽略不计，548 步起点的 Q 值为 1.7e-8，Actor 从中获得的梯度为零。**这是数学极限，不是迭代次数不够的问题。**
2. **脏数据恶性循环**：Actor 初始随机 → 产生大量无用在线数据（50% 采样概率）→ 稀释演示数据的梯度贡献 → Critic 学习变慢 → Actor 继续随机。
3. **人工介入悖论**：长程任务需要"从头引导到尾"，但论文警告这种"长且稀疏的介入"会导致 Q 值过估计。

### 1.3 折扣因子（γ）对长程任务的关键影响

γ 决定了 Agent 能"看多远"。有效视野 = 1/(1-γ)：

| γ | 有效视野 | Q(距终点100步) | Q(距终点300步) | Q(距终点548步) | 适用任务长度 |
|---|---------|---------------|---------------|---------------|------------|
| 0.97 | 33 步 | 0.048 | 0.0001 | **1.7e-8** | ~100 步 |
| **0.99** | **100 步** | **0.366** | **0.050** | **0.004** | **~300 步** |
| 0.995 | 200 步 | 0.606 | 0.223 | 0.064 | ~600 步 |
| 0.999 | 1000 步 | 0.905 | 0.741 | 0.578 | ~3000 步 |

HIL-SERL 论文使用 γ=0.97 是因为任务仅 ~100 步，有效视野 33 步足够覆盖。
对于 548 步的 gear assembly，**必须提高 γ 才能让 Q 值信号传播到任务起点**。

**γ 越高的代价**：Q 值估计方差越大、训练可能不稳定。γ=0.99 是平衡点：信号显著增强且训练稳定性可接受。

## 二、解决方案

### 2.1 方案概述（三管齐下）

在 `train_rlpd.py` 基础上新增 `train_rlpd_pretrain.py`，包含三个核心改进：

1. **提高折扣因子 γ=0.99**：扩大有效视野从 33 步到 100 步，让 Q 值在 548 步任务中仍有意义
2. **Learner 纯 Demo 预训练阶段**：在 Actor 启动前用 100% 演示数据训练 N 步，让 Bellman 在无脏数据干扰下充分传播
3. **动态采样比例**：正式训练时从高 demo 比例（80%）逐渐退火到标准 50%

### 2.2 三者如何协同工作

```
单独使用任何一个改进都不够，三者必须配合：

γ=0.99（扩大有效视野）
  └→ 让 Q 值在数学上有可能传播到起点（0.004 vs 1.7e-8）
  └→ 但需要足够的训练迭代让 Bellman 传播

预训练 5000 步（纯 demo 数据）
  └→ 在无脏数据干扰下，给 Bellman 充足时间传播 Q 值
  └→ γ=0.99 下，5000 步足够让信号传播数百步
  └→ Actor 学会至少后半段轨迹的策略

动态采样比例（80% → 50%）
  └→ 保护预训练建立的 Q 值不被在线脏数据冲刷
  └→ 随策略改善逐渐引入更多在线数据的多样性
```

### 2.3 训练流程对比

```
原始 RLPD (train_rlpd.py, γ=0.97):
──────────────────────────────────────────────────────
T0: Learner 加载 demo → 等待在线数据 → 50/50 训练
T0: Actor 随机策略 → 收集脏数据 → 长时间随机探索
问题: γ=0.97 有效视野仅 33 步，548 步起点 Q≈0
──────────────────────────────────────────────────────

预训练 RLPD (train_rlpd_pretrain.py, γ=0.99):
──────────────────────────────────────────────────────
阶段1: Learner 纯 Demo 预训练 5000 步（Actor 未启动）
        ↓ γ=0.99 下 Critic 建立更深远的价值地图
阶段2: 发布预训练参数给 Actor → 等待在线数据
        ↓ Actor 一开始就有基本能力，不再随机乱动
阶段3: 正式训练（demo 80% → 逐渐退火 → 50%）
        ↓ 保护 Q 值不被脏数据冲刷
──────────────────────────────────────────────────────
```

## 三、实现细节

### 3.1 文件结构

```
examples/
├── train_rlpd.py              # 原始 RLPD（保留不动）
├── train_rlpd_pretrain.py     # 新增：预训练版 RLPD
└── experiments/
    ├── mappings.py            # 新增 gear_assembly_pretrain 映射
    └── gear_assembly/
        └── config.py          # 新增 TrainPretrainConfig 类
```

### 3.2 新增配置参数（TrainPretrainConfig）

继承自 `TrainConfig`，新增/覆盖参数：

| 参数 | 默认值 | 基类值 | 说明 |
|------|--------|-------|------|
| `discount` | **0.99** | 0.97 | 覆盖基类，扩大有效视野到 100 步 |
| `pretrain_steps` | 5000 | — | 纯 demo 预训练步数 |
| `initial_demo_ratio` | 0.8 | — | 正式训练初始 demo 采样比例 |
| `final_demo_ratio` | 0.5 | — | 退火目标值（标准 RLPD） |
| `demo_ratio_anneal_steps` | 20000 | — | 退火所需步数 |

### 3.3 预训练阶段工作原理

预训练阶段使用 **100% 演示数据** 同时训练 Critic 和 Actor（与正式训练阶段使用完全相同的 SAC 算法）：

- **Critic**：在完整演示轨迹上反复学习 Bellman backup，Q 值从成功终点（r=1）逐步回传
- **Actor**：根据 Critic 的价值地图学习策略
- **Temperature**：自动调节探索 vs 利用的平衡
- **更新频率**：与正式训练相同（cta_ratio 次 Critic 更新 + 1 次联合更新）

**γ=0.99 下预训练 5000 步的预期效果**：
- 每步采样 256 条，5000 步 = 采样 1,280,000 次
- demo_buffer 仅 10,949 条，每条平均被采样 ~117 次
- 轨迹末尾 ~200 步的 Q 值充分传播并稳定（Q 值范围 0.13 ~ 1.0）
- 轨迹中间 ~200 步有微弱但非零的 Q 值（Q 值范围 0.004 ~ 0.13）
- 轨迹起点 ~148 步的 Q 值仍然很小（Q ≈ 0.004），但比 γ=0.97 提升约 200,000 倍

### 3.4 动态采样比例

正式训练阶段的 demo 比例随训练步数线性退火：

```
demo_ratio(step) = initial_ratio + (final_ratio - initial_ratio) × min(1, step / anneal_steps)
```

示例（默认参数）：

| 训练步数 | demo 比例 | demo batch | replay batch |
|---------|----------|------------|-------------|
| 0 | 80% | 205 | 51 |
| 5000 | 72.5% | 186 | 70 |
| 10000 | 65% | 166 | 90 |
| 15000 | 57.5% | 147 | 109 |
| 20000 | 50% | 128 | 128 |
| 20000+ | 50% | 128 | 128 |

## 四、使用方法

### 4.1 启动命令

与原始 `train_rlpd.py` 完全相同，只需：
1. 替换脚本名为 `train_rlpd_pretrain.py`
2. 使用 `--exp_name=gear_assembly_pretrain`（使用预训练配置）

**启动 Learner：**

```bash
python examples/train_rlpd_pretrain.py \
    --exp_name=gear_assembly_pretrain \
    --learner \
    --demo_path=./demo_data/gear_assembly_20_demos_2026-03-05_14-53-23_fixed_filtered.pkl \
    --checkpoint_path=./checkpoints/gear_assembly_rlpd_pretrain \
    --seed=42
```

**启动 Actor：**

```bash
python examples/train_rlpd_pretrain.py \
    --exp_name=gear_assembly_pretrain \
    --actor \
    --use_sim \
    --ip=localhost \
    --isaac_server_url=http://192.168.31.198:5001/ \
    --checkpoint_path=./checkpoints/gear_assembly_rlpd_pretrain \
    --seed=42
```

### 4.2 与原始 RLPD 对比实验

也可以使用 `--exp_name=gear_assembly`（原始 TrainConfig，不含预训练参数），
此时 `pretrain_steps` 默认为 0 且 γ=0.97，行为与原始 `train_rlpd.py` 完全一致。

## 五、参数调优建议

### 5.1 折扣因子（discount）

这是对长程任务影响**最大**的参数：

| γ | 有效视野 | 548 步起点 Q 值 | 建议场景 | 训练稳定性 |
|---|---------|---------------|---------|----------|
| 0.97 | 33 步 | 1.7e-8 | 短程任务 (~100步) | 最稳定 |
| **0.99** | **100 步** | **0.004** | **中长程任务 (~300-500步)** | **稳定** |
| 0.995 | 200 步 | 0.064 | 长程任务 (~500-800步) | 一般 |
| 0.999 | 1000 步 | 0.578 | 超长程任务，但风险高 | 可能不稳定 |

**推荐**：先用 γ=0.99 尝试，若初始阶段策略仍无改善，可提高到 0.995。

### 5.2 预训练步数（pretrain_steps）

| 场景 | 建议值 | 理由 |
|------|-------|------|
| 首次尝试 | 5000 | 平衡训练时间和效果 |
| 首次尝试效果不佳 | 10000 | 给 Bellman 更多传播时间 |
| 观察到 critic_loss 已收敛 | 当前值即可 | 更多步数无意义 |

**判断预训练是否充分的方法：**
- 观察预训练末期的 `critic_loss` 是否趋于平稳
- 预训练后 Actor 的行为是否有目的性（不再纯随机）

### 5.3 初始 Demo 比例（initial_demo_ratio）

- **0.8（推荐）**：大部分梯度来自演示数据，在线数据提供少量多样性
- **0.9**：更保守，适合在线数据质量极差的初期
- **0.5**：等于标准 RLPD，无动态调整效果

### 5.4 退火步数（demo_ratio_anneal_steps）

- 建议设为 **预期策略开始有效探索的步数**
- 10000-20000 步通常足够让策略从完全随机提升到基本可用

### 5.5 若仍不理想的进一步措施

如果 γ=0.99 + 预训练 + 动态采样的组合效果仍不足：

1. **提高 γ 到 0.995**：将有效视野扩展到 200 步，起点 Q 值提升到 0.064
2. **添加中间奖励（Dense Reward）**：在环境中为接近目标位置、对准齿轮轴等中间状态添加奖励，最有效的解决方案
3. **增加演示数据量**：更多轨迹 = 更丰富的状态覆盖 = 更快的 Q 值传播
4. **人工介入策略**：预训练后，Actor 在后半段轨迹能自主完成任务，人工只需引导前半段

## 六、技术原理

### 6.1 为什么在 RLPD 内部预训练，而不是 BC → RLPD 迁移？

| 方案 | 优势 | 劣势 |
|------|------|------|
| BC 预训练 → 迁移到 SAC | Actor 直接获得 BC 策略 | BCAgent 和 SACAgent 架构不同（BC 无 Critic/Temperature），权重迁移复杂且可能出错 |
| **RLPD 内部预训练** | 无需跨架构迁移；**Critic 同步预训练**，价值地图与 Actor 一致 | 预训练时间略长（同时训练 Critic） |

关键优势：RLPD 内部预训练同时训练了 **Critic**。这意味着 Actor 启动时不仅有基本策略，Critic 也已经建立了价值地图。而 BC→RLPD 迁移只能获得 Actor 权重，Critic 仍需从零开始。

### 6.2 为什么动态采样比例有效？

训练初期，在线数据（replay buffer）中充斥着低质量的探索数据。固定 50/50 采样意味着每个 batch 中 50% 是"脏数据"，会产生错误的 TD target，干扰 Critic 学习。

动态比例（初始 80% demo）的效果：
- **有效梯度占比提升**：80% 的 batch 来自高质量演示数据，梯度方向更准确
- **在线数据逐渐变好**：随着策略改善，在线数据质量提高，此时降低 demo 比例合理
- **最终回归 50/50**：策略成熟后，在线数据能提供 demo 未覆盖的状态多样性

### 6.3 为什么 γ 是最关键的参数？

γ 设定了 Q 值传播的**数学上限**。无论预训练多少步、采样比例如何调整，Q(s_0) 的理论收敛值就是 γ^N。

- γ=0.97, N=548: 上限为 1.7e-8 → **无论如何训练都没用**
- γ=0.99, N=548: 上限为 0.004 → **微弱但可用的信号**
- γ=0.995, N=548: 上限为 0.064 → **有效信号**

预训练和动态采样的作用是**让 Q 值在有限时间内尽可能接近这个理论上限**，但它们无法突破上限本身。所以提高 γ 是最根本的改进。

## 七、与原始 train_rlpd.py 的差异总结

| 特性 | train_rlpd.py | train_rlpd_pretrain.py |
|------|--------------|----------------------|
| 折扣因子 γ | 0.97（有效视野 33 步） | **0.99（有效视野 100 步）** |
| 预训练阶段 | 无 | 纯 demo 预训练 N 步 |
| 初始参数发布时机 | 等待在线数据后立即发布（随机参数） | 预训练完成后发布（已学习的参数） |
| 采样比例 | 固定 50/50 | 动态退火（80% → 50%） |
| Actor 启动时行为 | 随机乱动 | 有基本策略 |
| 适用场景 | 短程任务（~100 步） | 长程任务（~500+ 步） |
| 配置类 | TrainConfig | TrainPretrainConfig |
| exp_name | gear_assembly | gear_assembly_pretrain |

## 八、局限性与预期

**必须诚实说明**：即使使用 γ=0.99 + 预训练 + 动态采样，548 步任务仍然是挑战性的。

**可以预期的效果**：
- 轨迹后半段（距终点 ~200 步内）：Actor 学到明确策略
- 轨迹中段（距终点 200-400 步）：Actor 有微弱的方向感
- 轨迹前段（距终点 400+ 步）：Actor 可能仍需人工介入引导

**最优策略**：预训练后让 Actor 自主运行，**人工只在前半段无法自主完成时介入**。随着训练进行和在线数据质量改善，自主范围会从后半段逐渐扩展到全程。

如果需要初始阶段也有可靠策略，最有效的补充措施是**添加中间奖励**或**将 γ 进一步提高到 0.995**。
